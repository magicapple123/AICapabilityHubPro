## 8–12分钟演示

| 顺序 | 操作 | 核验点 |
|---|---|---|
| 1 | 普通用户登录→市场→多轮对话 | URL含capability_id=1，表单/目录价5积分 |
| 2 | 提交消息，打开调用记录与积分 | 实际cost、账单、流水、余额变化与requestId一致 |
| 3 | 选择长文本摘要，提交自己的材料 | capability_id=2、独立Schema、目录价3分与对应账单 |
| 4 | Settings修改昵称并刷新；查看积分筛选 | 资料持久化、普通角色、真实余额与入账/支出流水 |
| 5 | 创建短期限Key，关闭一次性Secret，再刷新 | no-store；列表仅掩码，不在截图/录屏/日志留下Secret |
| 6 | 用Key以JSON匿名POST兑换短JWT并调用API | TTL≤3600且不晚于Key期限；不在终端打印Token或Secret |
| 7 | 禁用Key后再次兑换 | 拒绝新兑换；不要宣称已签发JWT被即时撤销 |
| 8 | 普通用户进入Console/直接管理API | 真实服务器拒绝；伪造role头不能提权 |
| 9 | 独立管理员登录，新增QA分类和草稿能力 | Schema/价格保存，草稿市场不可见，禁止任意URL代理 |
| 10 | 编辑、上架、查看市场参数、下架 | 市场跟随真实状态；未知code即便上架也不可调试 |
| 11 | 管理员平台统计，展示CI/迁移/恢复证据 | 真实累计用量；角色撤销和故障负例见自动化报告 |

不要为现场演示随意降权/禁用真实用户、修改种子能力价格或断开现有服务。负例和软删除只针对隔离QA新建记录。

## 自动化验收

```powershell
python scripts/contract_lint.py
python -m pytest tests/tooling -q
mvn -q -f gateway/pom.xml package
pnpm --dir web lint
pnpm --dir web build
pnpm --dir web exec node --experimental-strip-types --test tests/chat-schema.test.ts
pnpm --dir web exec playwright install chromium --no-remove
python scripts/run_leader_e2e.py --catalog-mode market --browser
python scripts/run_leader_e2e.py --catalog-mode internal --browser
```

依赖Docker、Nacos、四服务独立venv及Gateway包。验收器创建自己的MySQL/卷、随机端口、Nacos group与子进程；管理员仅通过正常QA注册、在该工具自有库中精确提升新账号，再获取真实签名JWT。生产没有测试后门。

原10次/分钟兑换限流测试保留；后续Key成功兑换前显式等待61秒自然恢复，不关限流、不伪造来源。浏览器只屏蔽外部装饰图片，不替换业务响应。模型端为本地HTTP测试替身。

每次唯一`artifacts/leader-e2e/<编号>/`包括：

- `summary.json`：目录模式、真实链结果、内部契约与三个浏览器套件计数。
- `browser/browser-summary.json`：chat/settings/console实际断言及浏览器异常；只有三套件全通过才成功。
- 桌面/手机PNG：Secret关闭后采集，不保存trace、HAR、浏览器storage state或响应凭据。
- 每服务日志、browser-driver.log、resources.json：失败原因、专属资源和停止状态；失败证据不清理。

测试结束只停止本次自有进程与MySQL，保留容器/卷/日志。数据库pytest另须显式连接独立实例并严格检查JUnit零跳过；不能使用开发.env。
