# 演示环境搭建（容器版）

> 目标读者：负责录屏的组员。
> 目标：在一台**只装了 Docker Desktop** 的电脑上，把整套平台跑起来，用于录制演示视频。
> 全程约 15 分钟，其中 10 分钟是等镜像构建。

---

## 0. 这套环境和开发环境有什么区别

| | 开发环境（组长机器） | 本手册的容器环境 |
|---|---|---|
| 入口 | `http://localhost:5174`（Vite dev server） | `http://localhost`（Nginx + 构建产物） |
| 依赖 | JDK + Node + Python + MySQL + Nacos | 只要 Docker Desktop |
| 前端 | 热更新 | 生产构建，无 dev 浮层 |
| `/v1` 第三方入口 | Vite 代理 | Nginx 反代，`http://localhost/v1` |

两者跑的是**同一套代码、同一套数据库结构**。容器版更像正式产品，适合上镜。

---

## 1. 前置条件

- Windows 10/11 + Docker Desktop（已启用 WSL2 后端）
- 内存建议 ≥ 8 GB（Nacos + 5 个服务 + MySQL 常驻约 3 GB）
- 磁盘预留 ≥ 10 GB
- 能访问外网（首次构建要拉 Maven / PyPI / npm 依赖）

验证 Docker 可用：

```powershell
docker version
docker compose version
```

两条都要有输出。若 `docker version` 报错，先启动 Docker Desktop 并等右下角鲸鱼图标变绿。

---

## 2. 你会拿到两样东西

1. **代码仓库**：`git clone https://github.com/magicapple123/AICapabilityHubPro.git`
2. **`deploy/.env` 配置文件**：由组长**私下**发给你（微信/网盘），**不要提交、不要发群**

> ⚠️ `.env` 里有数据库密码、JWT 签名密钥、供应商主密钥和上游模型 Key。
> 它被 `.gitignore` 排除，永远不会进仓库——这不是遗漏，是设计。

拿到后放到 `deploy/.env`（覆盖仓库里没有的这个文件）。

## 3. 启动

```powershell
cd AICapabilityHubPro\deploy
docker compose --env-file .env --profile app up -d --build
```

首次会构建 5 个镜像（网关 Java、4 个 Python 服务、前端 Nginx），**10 分钟左右**。
看到 `Container aihub-pro-xxx  Started` 即完成。

查看状态，等所有服务变成 `healthy`：

```powershell
docker compose --env-file .env --profile app ps
```

`gateway` 的 `STATUS` 需要等 `healthy`（它要等 Nacos 注册 + 下游就绪，最长 2 分钟）。
**没变 healthy 就不要开始录。**

## 4. 启动后自检（6 条，必须全过）

### ① 页面能打开

浏览器访问 `http://localhost` → 出现登录页。

> 端口 80 若被占用，把 `deploy/.env` 的 `NGINX_PORT` 改成 `8088`，重新 `up -d`，之后访问 `http://localhost:8088`。

### ② 演示账号能登录

`demo` / `demo123456`

### ③ 后台配置是"整理过"的

进入 **运营后台 → 模型服务**，应看到：

- 供应商 **2 个**：`DeepSeek`（enabled）、`DashScope 通义万相`（enabled）
- 能力 **4 个**，对外模型名分别是 `deepseek-chat` / `deepseek-summary` / `deepseek-vision` / `wanx-image`

如果供应商是空的、或能力只有 3 个，说明演示种子没执行——见第 7 节。

### ④ 对话是真调用，不是 Mock

在 **能力市场 → 多轮对话 → 去调试** 发一句「用一句话介绍你自己」。

- 正常：2～5 秒后出现中文回复
- 异常：回复里带「模拟」或秒回固定文案 → 说明还在 Mock 模式

命令行验证（更可靠）：

```powershell
docker compose --env-file .env logs ai-chat-service | Select-String "mock"
```

没有输出即正常；出现 `USE_MOCK` 相关日志说明没读到 `.env` 里的 `USE_MOCK=false`。

### ⑤ 第三方入口通

先在 **设置页** 创建一把 API Key（`sk_` 开头，**只显示一次，立刻复制**），然后：

```powershell
curl.exe -H "Authorization: Bearer sk_你的Key" http://localhost/v1/models
```

应返回 `{"object":"list","data":[{"id":"deepseek-chat",...}]}`。

> 只有 `deepseek-chat` 一个模型是**正确的**。摘要、文生图、视觉走的是平台自有协议，
> 不发布到 OpenAI 兼容端点；视觉的入参是 `image_url`，不是 `messages`，发布门禁会拦掉。
> 这不是 bug，答辩时是加分点。

### ⑥ 账单对得上

发完对话后进 **用量页**，应出现一条调用记录：能力=多轮对话、扣 5 积分、状态成功。

## 5. 录制前的重置（每次彩排后执行）

彩排会消耗积分、产生账单。正式录之前把状态归位：

```powershell
cd AICapabilityHubPro\deploy
docker compose --env-file .env exec -T mysql mysql -uroot -p你的数据库密码 --default-character-set=utf8mb4 < mysql/init/07_demo_seed.sql
```

这会：恢复 2 个供应商、4 个能力与文案、demo 账号余额回 100。
**不会**删除历史账单（账单是追加型记录，删了反而不真实）。

如果想让用量页从零开始：

```powershell
docker compose --env-file .env exec -T mysql mysql -uroot -p你的数据库密码 -e "DELETE FROM billing_db.t_call_record; DELETE FROM ai_chat_db.t_chat_message; DELETE FROM ai_chat_db.t_chat_session;"
```

## 6. 录制时的三个"别点"

| 位置 | 现象 | 原因 |
|---|---|---|
| 视觉理解的「去调试」 | 400 / 调用失败 | 多模态通道未接入，它只是展示位 |
| 长文本摘要的供应商绑定 | 返回「模型服务暂时不可用，已返回兜底回复」 | `summary 执行器 + 供应商通道` 会静默降级，已实测 |
| 模型服务的「测试」按钮（DashScope 行） | 可能超时 | 阿里云接口对网络敏感，非必要不点 |

前两条不是演示环境的问题，是产品当前边界。答辩被问到时按第 8 节话术回答。

## 7. 常见问题

**供应商页是空的 / 能力只有 3 个**
演示种子只在**数据库首次初始化**时执行。若之前起过一次（volume 已存在），改完种子不会重跑：

```powershell
cd AICapabilityHubPro\deploy
docker compose --env-file .env --profile app down -v   # -v 会删除数据卷
docker compose --env-file .env --profile app up -d
```

**对话回复是「模拟」内容**
`deploy/.env` 里 `USE_MOCK` 必须是 `false`，且 `MODEL_API_KEY` 非空。改完重启：

```powershell
docker compose --env-file .env --profile app up -d --force-recreate ai-chat-service
```

**登录报 401 / 一直转圈**
网关与 user-service 的 `JWT_SECRET` 必须一致。检查 `deploy/.env` 里 `JWT_SECRET` 非空，然后 `up -d --force-recreate`。

**`/v1/models` 返回 HTML**
说明 Nginx 没把 `/v1` 转发出去。确认拉的是**最新代码**（`git pull`），
`deploy/nginx/nginx.conf.template` 里应有 `location ^~ /v1/`。

**端口 80 被占用**
改 `deploy/.env` 的 `NGINX_PORT=8088`，`up -d` 后访问 `http://localhost:8088`。

**想彻底清干净**

```powershell
docker compose --env-file .env --profile app down -v
docker image prune -f
```

## 8. 答辩时的口径

被问「为什么平台有 4 个能力，第三方只有 1 个模型」：

> `/v1/models` 只发布能被 OpenAI Chat 协议承载的能力，判据是能力入参 Schema 的 `required`
> 是否包含 `messages`。摘要走 summary 执行器、生图走 image-generate、视觉要 `image_url`，
> 都不符合 Chat 协议，所以在平台目录里可用、但不在该端点发布。

被问「供应商是干什么的」：

> 能力决定"怎么跑"，供应商决定"跑在哪"。对话能力绑定 DeepSeek 通道，
> 文生图绑定 DashScope；摘要和视觉暂走系统级默认配置。

## 9. 和组长环境的对齐点

| 项 | 值 | 说明 |
|---|---|---|
| 数据库 | 容器内 MySQL 8.4 | 无需外部安装 |
| 演示账号 | `demo` / `demo123456` | 余额 100 |
| 后台管理员 | `admin` / 见 `deploy/.env` 的 `BOOTSTRAP_ADMIN_PASSWORD` | 首次启动自动创建 |
| 对外模型名 | `deepseek-chat` | 与组长环境一致 |
| 供应商主密钥 | `PROVIDER_MASTER_KEY_V1` | **必须与组长一致**，否则供应商密文解不开 |

如果你换成自己的上游 Key：只能改 `MODEL_API_KEY`，**不要改 `PROVIDER_MASTER_KEY_V1`**。
