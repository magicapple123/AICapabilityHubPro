## 二、发现并修复的问题

### 1. 真实模型调用必然降级（P0）

- **现象**：把 `USE_MOCK` 设为 false 后，任何调用都返回"模型服务暂时不可用"，`degraded=true`、`error_code=5002`，实际扣 0 分。
- **根因**：`ChatCompletionRequest.model` 默认值写死 `mock-model`，请求不传 model 时就把这个假名字发给真实供应商，对方必然拒绝。
- **修复**：新增 `MODEL_NAME` 配置（`services/ai-chat-service/.env`），服务端默认模型名由配置决定；请求显式传 `model` 时仍以请求为准。
- **改动**：`app/core/config.py`、`app/schemas/chat.py`、`app/service/capability_adapters.py`、`.env.example`、README。
- **验证**：真实回调 `model=deepseek-flash`、`degraded=false`、`cost=5`；传非法模型名则按契约降级且不计费。

### 2. 种子数据双重编码，昵称显示成乱码（P0）

- **现象**：账号设置页昵称显示 `æ¼"ç¤ºç”¨æˆ·`，头像首字是 "A"；能力名在部分页面靠前端兜底函数才显示正常。
- **根因**：`deploy/mysql/init/*.sql` 与 `services/*/sql/*.sql` 是 UTF-8，但容器首次初始化时 MySQL 客户端连接字符集为 latin1，导致字节被二次编码入库。
- **修复**：
  - 13 个初始化脚本首行补 `SET NAMES utf8mb4;`，新装环境不再复现；
  - 现有库用 `CONVERT(BINARY(CONVERT(col USING latin1)) USING utf8mb4)` 逐表回正，种子行按原值校正；
  - 前端 `displayText()` 兜底保留，兼容历史数据。
- **验证**：库里昵称/能力名/分类名均为正确中文，页面不再出现乱码。

### 3. 网关被环境变量劫持端口（P1，现场会起不来）

- **现象**：`python scripts/start_pro_local.py gateway` 报 `Web server failed to start. Port 29477 was already in use`，而配置写的是 8080。
- **根因**：当前 shell 环境存在 `SERVER__PORT=29477`（宿主程序注入），Spring 的宽松绑定把它当作 `server.port`，环境变量优先级高于 `application.yml`。
- **修复**：`scripts/start_dev.py` 启动网关时显式传 `-Dserver.port=<GATEWAY_PORT 或 8080>`；`scripts/leader_e2e/runtime.py` 启动 jar 时补 `--server.port=<随机端口>`。系统属性/命令行参数优先级更高，环境变量不再能劫持。
- **验证**：按文档命令启动，Netty 正常监听 8080；改用 `GATEWAY_PORT=18081` 也按预期生效。

### 4. 移动端调用记录把页面撑宽（P1）

- **现象**：390px 下 `.records-table` 宽 520px，页面 `scrollWidth` 487px，"调用时间"列被裁掉且无横向滚动提示。
- **修复**：`responsive.css` 增加 767px 断点，把调用记录改为逐条卡片（服务名/模型一行，状态、费用、时间一行），非紧凑表格在手机上省略"耗时"列。
- **验证**：工作台与调用记录页 `scrollWidth == 390`，截图见 `artifacts/_audit/shots/17-mobile-recent-fixed.png`。

### 5. 弹窗高度超出视口（P2）

- **现象**：900px 高的窗口里，"登记新能力"弹窗高约 950px，保存按钮落在视口外，需要滚动整层遮罩才能点到。
- **修复**：公共 `Modal` 的 body 增加 `maxHeight: calc(100vh - 210px)` 与内部滚动，底部按钮始终可见。
- **验证**：弹窗在 900px 视口内完整显示，保存按钮可直接点击。

### 6. 运营搜索文案与实际检索范围不符（P2）

- **现象**：搜索框提示"搜索能力名称或编码"，后端只匹配名称与描述，按编码搜不到。
- **修复**：`capability_repository._manage_conditions` 的 keyword 条件增加 `Capability.code`。
- **验证**：`keyword=chat-comp` 能检索到"多轮对话"；按名称/描述检索行为不变。
