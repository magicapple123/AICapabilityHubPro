# Pro 升级验收记录模板

本表为三名成员提交升级功能时使用。所有业务用例初始为未执行，不能以基线测试或本地 skipped 代替。每项填写提交 SHA、执行者、日期、实际结果、测试日志或 PR 中的证据。

| 编号 | 场景和预期 | 负责人 | 状态 |
|---|---|---|---|
| PRO-01 | 注册默认普通用户；不能自助指定 admin | 黄禹菲 | 未执行 |
| PRO-02 | 普通用户直接调用能力/分类管理及全局统计，被服务器拒绝 | 三人 | 未执行 |
| PRO-03 | 管理员可上下架能力；角色降权后旧 JWT 无法继续管理 | 三人 | 未执行 |
| PRO-04 | 伪造 X-User-*、role、requestId 不能获得额外权限 | 黄岑果 | 未执行 |
| PRO-05 | 管理授权依赖故障时，管理操作失败关闭 | 黄禹菲、夏思凯 | 未执行 |
| PRO-06 | API Key secret 只在创建时返回一次，列表/日志无 secret/hash | 黄禹菲 | 未执行 |
| PRO-07 | 正确 Key 可兑换受 TTL 上限控制的 JWT；错误、禁用、过期 Key 均失败 | 黄禹菲、黄岑果 | 未执行 |
| PRO-08 | market 不包含 service/path/secret；体验入口传递选中能力 ID | 夏思凯 | 未执行 |
| PRO-09 | 聊天/摘要输入与能力 Schema 匹配，错误输入在模型前被拒绝 | 黄岑果、夏思凯 | 未执行 |
| PRO-10 | 未知、草稿、下架及不支持 code 均不执行模型 | 黄岑果 | 未执行 |
| PRO-11 | 单次成功的能力 ID、登记价、账单 cost、积分流水一致 | 三人 | 未执行 |
| PRO-12 | 初始积分不足时模型调用为 0，无成功计量记录或扣款 | 黄禹菲、黄岑果 | 未执行 |
| PRO-13 | 同幂等 requestId 重试不重复扣款；冲突 payload 被拒绝 | 黄禹菲 | 未执行 |
| PRO-14 | Mock 不访问外部模型；真实模型超时降级不扣款 | 黄岑果 | 未执行 |
| PRO-15 | 跨用户查询会话、积分、明细被拒绝或仅返回自己数据 | 黄岑果、黄禹菲 | 未执行 |
| PRO-16 | 旧数据库增量升级保留已有数据；不能依靠重跑 seed 或清空数据卷 | 对应服务负责人 | 未执行 |
| PRO-17 | 三人代码在相同提交通过 CI、契约、Web 构建和实际网关联调 | 三人 | 未执行 |

## 每项证据填写格式

- 用例编号：
- 提交 SHA / PR：
- 执行环境及数据隔离方式：
- 操作步骤和期望结果：
- 实际响应或断言结果：
- requestId 与匹配账单/积分证据（适用时）：
- 执行者与时间：
- 失败问题和对应修复提交：

不得在证据中保留用户密码、JWT、Key secret 或模型凭据。并发及跨服务网络故障尚无分布式原子性保证，相关限制按计划如实记录。
