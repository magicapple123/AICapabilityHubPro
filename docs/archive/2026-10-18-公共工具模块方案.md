# 公共工具实施边界

本次只完成共用环境、启动、静态检查和交付记录，不实现三名成员的业务任务。旧仓库和分支保持不变。现有受控文件的恢复基线为提交 `73fda4e`；新增本地配置只允许首次创建，不覆盖任何现存 `.env`。

| 文件 | 职责 | 预计行数 |
|---|---|---|
| `scripts/init_dev.py` | 环境初始化入口和可选依赖安装 | 80 |
| `scripts/devtools/environment.py` | 配置解析、路径和各服务解释器定位 | 100 |
| `scripts/devtools/initialization.py` | 生成一致的本地密钥和环境配置，仅创建缺失文件 | 180 |
| `scripts/start_dev.py` | 在当前终端启动一个指定组件 | 90 |
| `scripts/smoke_check.py` | 只读检查公开市场、网关认证和内部路径隔离 | 170 |
| `scripts/check_test_report.py` | 读取 pytest JUnit，拒绝 CI 数据库用例静默跳过 | 80 |
| `scripts/Test-ProEnvironment.ps1` | 检查工具和公共配置，不启动服务 | 120 |
| `scripts/Invoke-QualityGate.ps1` | 聚合检查并生成唯一结果报告，恢复环境变量 | 160 |
| `scripts/contract_lint.py` | 仅检查版本控制候选文件，避免误报合法本地配置 | 150 |
| `tests/tooling/` | 验证配置不覆盖、密钥一致、测试缺失/跳过判定和 HTTP 负例 | 每文件 100–200 |

依赖方向：初始化/启动入口依赖 `devtools`；配置模块不反向引用入口，不导入业务服务。按配置解析→首次初始化→组件启动→只读检查→质量聚合的顺序实施。

验证命令：`python -m pytest tests/tooling -q`、PowerShell 语法解析、`python scripts/contract_lint.py`、`docker compose -f deploy/docker-compose.yml config --quiet`、Web lint/build 和 Gateway/四服务测试。CI 数据库报告要求执行用例数大于零且 skipped 为零。

本地部署为 Pro 使用单独命名的容器和数据卷。首次配置默认保留原端口；若原项目也在运行，先停止其进程或另配端口，工具不代为停止原项目。
