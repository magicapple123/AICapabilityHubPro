## 7. 用户自验手册（非开发人员可照做）

**准备**：确认容器在跑

```powershell
docker ps --format "{{.Names}}\t{{.Status}}" | Select-String aihub-verify
# 期望 9 个容器都出现 (healthy)
```

打开 <http://127.0.0.1:28088>，用部署时创建的管理员登录。

### 第一步：看「用户与用量」（P5/P7/P10）

1. 顶栏进入 **运营后台**，应看到 5 个页签：能力管理 / 分类管理 / **用户与用量** / 操作审计 / 模型服务。
2. 直接访问旧地址 `/console?tab=statistics`，应自动跳到 `tab=users-usage`（地址栏可见）。
3. 名单默认「近 30 天消耗降序」；把排序切到「调用次数」，第一行应变成调用次数最多的用户。
4. 在搜索框输入某个用户 ID（纯数字），应能搜到该用户——这是旧版本做不到的。
5. 点某行「详情」：抽屉里有近 30 天趋势、最近 10 条调用、Key 列表、**按 Key 调用分布**、**日预算**编辑框。
6. 点「调分」，输入 `-999999`：应立即出现「最多可扣 X」且「确认扣减」按钮变灰；改成 `+50` 并填写原因后提交，提示里的新余额应等于列表刷新后的余额。
7. 日预算填 `5` 保存 → 用该账号连续调两次同一能力，第二次应返回 `3003`；改回 `0` 立即恢复不限。

### 第二步：看「设置 → API Key → 使用方法」（P3/P6）

1. 设置页切到 **API Key**，页头与每行都有「使用方法」。
2. 打开抽屉，确认：红色提示写明「两套凭证不可互换」；三个页签分别是 OpenAI 兼容 / 平台 API / 客户端配置；OpenAI 页签里能看到当前可用的模型别名。
3. 新建一把 Key，创建成功弹窗里应同时有「查看使用方法」与「不可互换」提示；关闭后 Secret 不再可见（只剩掩码）。
4. 用抽屉里的 OpenAI curl 调一次，响应应带 `platform_cost`；到 **调用记录** 页应能看到「来源 = OpenAI 兼容」，详情里有「调用 Key」编号。

### 第三步：看「能力管理 → 登记新能力」（P8/P9）

1. 点「登记新能力」，弹窗应是 720px、分四组：基本信息 / 执行配置 / 计价 / 展示 + Schema。
2. 选执行器 `chat`，价格模式选「按 token」→ 只出现输入/输出两个单价框；改选「按件」→ 只出现单价与单位。
3. 「Schema 模板」标签应在同一行（不折行）；文本框失焦时若 JSON 非法，错误出现在 Schema 下方。
4. 不选执行器时，「初始状态」里的「已上架」应是灰的并写明原因。
5. 保存后到 **能力市场**：该能力应显示「支持调试」而不是「暂无执行器」。

### 第四步：看审计表格（P4）

运营后台 → 操作审计：把窗口依次拉到 1440 / 1280 / 1024 宽，**不应出现底部横向滚动条**；`requestId` 列始终可见，点复制得到完整 36 位。

## 8. 风险与回滚

**本轮引入的新契约**

| 类型 | 内容 |
|---|---|
| 表字段 | `t_capability.openai_alias`；`t_call_record.api_key_id` / `entrypoint`（+ 索引） |
| 错误码 | `2009` 供应商不可用（仅 `resolve_runtime` 抛出，`/v1` → 503） |
| 接口 | `GET /api/billing/admin/users/usage`、`GET /api/billing/admin/users/{id}/keys-usage`、`PUT /api/user/admin/users/{id}/budget`、`GET /api/capability/models` |
| 出参 | 市场列表增 `executor`；`CallRecordOut` 增 `api_key_id`/`entrypoint`；Responses 增 `platform_warnings` |
| 请求头 | `X-User-Key-Id`（仅网关写入，外部同名头被剥离） |
| JWT | exchange 令牌增 `key_id` claim（普通登录令牌不变） |
| 环境变量 | `REQUEST_BUDGET_SECONDS`、`PROVIDER_BREAKER_ENABLED`、`PROVIDER_BREAKER_FAILURE_THRESHOLD`、`PROVIDER_COOLDOWN_SECONDS`（均有默认值） |

**回滚步骤**

1. 代码：按条目 revert（P1/P2/P11/P12 集中在 ai-chat + capability；P6/P10/P14 在 user/billing/gateway；P5/P7/P8/P9 在 web）。
2. 数据库：新增列均为可空/有默认值，**不删列也能回滚**；确需回收时先 `ALTER TABLE ... DROP COLUMN` 前备份证据。
3. 熔断：设 `PROVIDER_BREAKER_ENABLED=false` 即可关闭，不需要改代码。
4. 预算：把 `daily_points_limit` 改回 `0`（不限）。
5. 别名：清空 `openai_alias` 或将 `OPENAI_COMPAT_MODEL_MAP` 改回静态值（显式配置优先级高于动态目录）。
