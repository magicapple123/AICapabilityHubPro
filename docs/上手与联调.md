# AICapabilityHub Pro 本地上手与联调

现行开发入口为 [Pro 开发指南](../AICapabilityHubPro-开发指南.md)。以下为推荐的并行运行步骤：原项目可保持运行，Pro 使用独立中间件端口和数据卷。

## 代码与环境

PR #1/#2 已合入 main，成员从最新 origin/main 创建自己的分支，PR 目标 main。不要从尚未同步的 develop 开始，也不向原 AICapabilityHub 仓库推送。

需 Python 3.12、JDK 21、Maven 3.9.x、Node 24、pnpm 11、Docker Desktop。根目录执行：

```powershell
Set-Location D:\AICapabilityHubPro
python scripts/init_dev.py --install
.\scripts\Test-ProEnvironment.ps1
python scripts/start_pro_local.py middleware
```

初始化只创建缺失配置，网关/user 共用签名密钥，DB 密码保持一致；重复执行保留 .env。发现配置冲突先核对，不删配置或删数据卷“修复”。

## 组件启动

每条命令各占一个终端，均在 Pro 根目录：

```powershell
python scripts/start_pro_local.py user-service
python scripts/start_pro_local.py capability-service
python scripts/start_pro_local.py billing-service
python scripts/start_leader_dev.py ai-chat-service --catalog-mode market
python scripts/start_leader_dev.py gateway
python scripts/start_leader_dev.py web
```

MySQL 3307、Nacos 8849/9849、Sentinel 8859；应用为 Gateway 8080、四服务 8081/8082/8083/8090、Web 5173。Pro 容器/卷名称见[并行配置](双项目并行联调.md)。

显式 market 读取旧目录已上架详情，仍验证 Schema/状态和登记价。默认 internal 要求内部详情服务端就绪；缺失会报 4002，不自动回退。切换后需重启对应组件并验证，不能混用 start_dev.py 的默认中间件端口。

## 访问与只读检查

浏览器 http://localhost:5173，本地公开账号 demo / demo123456，低余额 demopoor / demo123456。默认真实登录；USE_MOCK 只控制模型执行，结果明确 mock=true。聊天 /chat?capability_id=1，摘要 /chat?capability_id=2。

```powershell
python scripts/smoke_check.py
```

烟测是经 Gateway 的无凭证 GET，检查市场、未登录保护、internal 隔离和四服务 health，不调用模型或扣分。health 不代替真实 DB/计量验收。

## 验证与排障

- 代码与接口先做契约检查和相关单测，数据库用独立实例；见[质量门禁](质量门禁说明.md)。
- 完整可复现链使用 scripts/run_leader_e2e.py，包含独立数据库/端口/进程及模型 HTTP 替身，见[演示交接](组长功能演示与交接.md)。
- 4002：核对目录模式、端点是否交接、Nacos 注册/group 和依赖返回结构；不要改成假成功。
- 1001：核对签名密钥、issuer、JWT；禁用账号由业务实时检查。
- 503：网关已启动但路由实例未就绪；检查注册，不用直连替代经网关通过。
- 端口占用：确认进程属于哪套项目，不结束未知进程，不删卷。
- 时间窗口不一致：测试 MySQL 的 NOW() 与应用主机业务日期需对齐，特别是北京时间/UTC。
- Nginx、构建和代理配置详见 [Web README](../web/README.md)。

旧默认端口入口 scripts/start_dev.py 仅供明确选择默认模式的环境；本页不要求覆盖现有 .env。已有业务库升级由服务负责人提供增量迁移，初始化/seed 不等于迁移。
