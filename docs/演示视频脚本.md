# 演示视频脚本（一镜到底 · 带解说）

> 目标时长 **7～8 分钟**，单人旁白，全程不剪辑。
> 环境：容器版（`http://localhost`），搭建见《演示环境搭建-容器版.md》。

---

## 一、开录前的 30 分钟

### 1. 环境就绪

```powershell
cd D:\AICapabilityHubPro\deploy   # 按你的实际克隆路径替换
docker compose --env-file .env --profile app ps
```

9 个容器全部 `healthy`。`gateway` 没 green 就不要开录。

### 2. 重置演示数据

```powershell
docker cp mysql\init\07_demo_seed.sql aihub-pro-mysql:/tmp/demo_seed.sql
docker exec aihub-pro-mysql mysql -uroot -p你的密码 --default-character-set=utf8mb4 -e "source /tmp/demo_seed.sql"
docker cp demo\bind_chat_provider.sql aihub-pro-mysql:/tmp/bind_demo.sql
docker exec aihub-pro-mysql mysql -uroot -p你的密码 --default-character-set=utf8mb4 -e "source /tmp/bind_demo.sql"
```

输出里应看到：供应商 2 条、能力 4 条、demo 余额 100。
第二条不能省——种子为了兼容 CI 刻意不绑定供应商，不补这一步后台会显示「未被任何能力引用」。

### 3. 预热（关键）

正式录之前**先真实调一次**，把上游连接、Nacos 路由、模型冷启动全部走热：

```powershell
curl.exe -H "Authorization: Bearer sk_你的Key" http://localhost/v1/models
```

否则镜头里第一次调用会慢 2～3 秒，看起来像卡住。

### 4. 桌面与浏览器

| 项 | 设置 |
|---|---|
| 分辨率 | 1920×1080，浏览器缩放 **125%**（投屏后字才够大） |
| 浏览器 | 独立窗口，隐藏书签栏（Ctrl+Shift+B），只留一个标签页 |
| 通知 | Windows 专注助手开「仅闹钟」；退出微信/QQ/钉钉 |
| 鼠标 | 开「指针位置高亮」或装鼠标点击可视化，观众才跟得上 |
| 输入法 | 切英文，避免中文候选框弹出 |
| 剪贴板 | 提前把 API Key 复制好 |

### 5. 预建 API Key（不要现场建）

现场创建会暴露完整 `sk_` 明文。提前在设置页建好，名字 `demo-video`，把 Secret 粘到：

```
D:\AICapabilityHubPro\deploy\demo\demo-key.txt
```

只放一行 `sk_...`，不要引号、不要多余空格（该文件已在 `.gitignore` 里，不会入库）。

仓库自带 `deploy\demo\demo-v1.ps1`，会读这个文件并依次打印**模型列表**和**一次真实对话**。
先自测一遍：

```powershell
cd D:\AICapabilityHubPro\deploy\demo
powershell -ExecutionPolicy Bypass -File .\demo-v1.ps1
```

- 正常：先输出 `{"object":"list",...}`，再输出带 `usage` / `platform_request_id` / `platform_cost` 的 JSON
- 若 `NGINX_PORT` 不是 80：加 `-BaseUrl http://localhost:8088`
- 报「缺少 demo-key.txt」：文件没放对目录
- 报 `401`：Secret 复制不全或用了 `ak_` 开头的 Access Key（必须是 `sk_`）

### 6. 确认管理员能进后台

第 8 段要进运营后台，但容器栈**不会自动建管理员**（种子只有 demo 三个账号）。
按搭建手册 4⑦ 建好 `admin` 并**重新登录**一次，确认 `/console` 能打开——
否则录到第 8 段会卡在 2007 权限错误上。建议用另一个浏览器窗口登录 admin，
录屏时两个窗口切换，不用反复登录登出。

## 二、分镜表

> 「台词」是可以直接照读的口语稿，不必逐字背。

### 第 1 段 · 登录（0:00 – 0:40）

| | |
|---|---|
| 画面 | 登录页 → 输入 `demo` / `demo123456` → 进入概览 |
| 操作 | 慢速输入用户名，密码框一次填完，回车 |

**台词**
> 这是我们做的 AI 能力开放平台。它解决一个具体问题：模型能力分散在各家厂商，
> 计费、鉴权、限流各写一套。我们把它们收成一个统一入口——用户按次付费，
> 第三方用标准 OpenAI 协议接入，运营在后台配置模型和价格。

### 第 2 段 · 概览（0:40 – 1:10）

| | |
|---|---|
| 画面 | 概览页的可用次数、本月消耗、最近调用 |
| 操作 | 鼠标沿数据卡片横向划过 |

**台词**
> 登录后是用户视角的概览：剩余积分、本月消耗、最近调用。
> 积分是平台内部的计价单位，一次调用扣一次，失败不扣。

### 第 3 段 · 能力市场（1:10 – 1:50）

| | |
|---|---|
| 画面 | 能力市场 3 张卡片 |
| 操作 | 依次悬停 3 张卡，停在「多轮对话」 |

**台词**
> 能力市场里是当前对外展示的三类能力：多轮对话 5 积分一次、长文本摘要 3 积分、文生图 20 积分。
> 价格不是写死在代码里的，是运营在后台按能力配置的。
> 每张卡片的表单，是根据这个能力的参数 Schema 动态渲染出来的——加一个能力，前端不用改代码。

> 补充（有人问"后台不是有四个能力"时）：第四个是视觉理解，Schema 和对外模型名都配好了，
> 但多模态通道还没接入，所以状态留在**草稿**、没有上架——后台可见、市场和第三方列表都看不到它。
> 等通道接进来，把状态改成在线就发布了。

### 第 4 段 · 真实对话（1:50 – 3:20）★ 核心

| | |
|---|---|
| 画面 | 点「多轮对话 → 去调试」，输入问题，提交，等待返回 |
| 操作 | 输入「用三句话说明这个平台的价值」，回车；等结果出来后，**鼠标停在右下角的耗时/费用/requestId 上** |

**台词**
> 我们直接发一次真实请求。注意这里不是演示数据——它会真的打到上游模型。
> （等待 2 秒）返回了。右侧这行是这次调用的完整凭据：实际耗时、扣除的积分、
> 以及平台生成的 requestId。这个 requestId 在账单、日志、审计里都能对上，
> 出问题可以一路追到底。

**若超过 5 秒没返回**（不要慌，继续说）：
> 首次调用要建立上游连接，会稍慢一些；后面的请求会走热连接。

### 第 5 段 · 用量与账单（3:20 – 4:00）

| | |
|---|---|
| 画面 | 用量页 → 刚产生的那条记录 → 积分流水 |
| 操作 | 点开最新一条，展示能力名、扣费、状态 |

**台词**
> 刚这次调用立刻出现在用量页：能力、模型、扣了 5 积分、状态成功。
> 下面是积分流水，每一次入账支出都有记录。这套账是计费服务独立管的，
> 和业务服务分开，所以业务出问题也不会把账算错。

### 第 6 段 · 接入信息（4:00 – 4:50）

| | |
|---|---|
| 画面 | 设置页 → API Key 列表（掩码）→ 「使用方法」抽屉 |
| 操作 | 展开抽屉，鼠标划过 Base URL 和 model 两个字段 |

**台词**
> 第三方要接入，在这里管理 API Key。我这条是提前建好的——明文只在创建那一刻显示一次，
> 之后列表里只剩掩码，服务端也只存哈希，谁也取不回原文。
> 接入信息就三样：Base URL、Key、模型名。这里的模型名是自动填充的，
> 因为平台会按当前上架的能力动态生成可用模型列表。

### 第 7 段 · 第三方调用（4:50 – 5:40）

| | |
|---|---|
| 画面 | 终端窗口，执行预置脚本（脚本里读 Key，命令行不出现明文） |
| 操作 | `cd D:\AICapabilityHubPro\deploy\demo` → `powershell -ExecutionPolicy Bypass -File .\demo-v1.ps1`，先出模型列表，再出对话 JSON |

**台词**
> 我们用标准 OpenAI 协议调一次。先看模型列表——只有 `deepseek-chat` 一个。
> 这不是配置少了：摘要、文生图、视觉走的不是 Chat 协议，不会发布到这个端点，
> 但它们都在平台目录里正常可用。
> 再发一条消息……返回结构和 OpenAI 完全一致，可以直接接进任何兼容客户端。

### 第 8 段 · 运营后台（5:40 – 7:00）

| | |
|---|---|
| 画面 | 运营后台 → 模型服务（**用 admin 登录的那个窗口**，不是 demo） |
| 操作 | 先讲供应商两行，再讲能力四行，最后停在「多轮对话」的对外模型名输入框 |

**台词**
> 切到运营视角。这个页面回答两个问题：能力从哪来，以及怎么卖。
>
> 上半部分是能力：四个能力，各自的执行器、绑定的供应商、单价、输出上限、
> 是否在市场展示。执行器决定"怎么跑"，供应商决定"跑在哪"——比如对话绑定 DeepSeek 通道，
> 文生图绑定阿里云通义万相。
>
> 下半部分是供应商：地址、协议、密钥（只显示后四位）、连通性测试。
> 密钥是加密存的，页面上看不到也导不出。
>
> 这行「对外模型名」就是第三方看到的模型名。改完保存，五秒内第三方列表就会跟着变。
> 但它不是随便填的——只有入参接受 `messages` 的能力才会真正发布出去，
> 否则就会出现"列表里有、一点就报错"的情况。

### 第 9 段 · 收尾（7:00 – 7:30）

| | |
|---|---|
| 画面 | 回到概览页或架构图（如有） |
| 操作 | 鼠标停下，不再移动 |

**台词**
> 整个平台是六个可独立部署的服务：网关、用户、能力目录、计费、AI 执行、前端，
> 加四个数据库。全部容器化，一条命令可以在一台干净机器上拉起来。
> 我们做的事，是把"模型能用"变成"模型可运营"。

## 三、三条纪律

1. **一镜到底 = 不许拼接**。出错就重录整条，不要剪。观众能看出来，评委更能。
2. **不点三样东西**：视觉理解的「去调试」、摘要能力的供应商绑定、DashScope 的「测试」。原因见搭建手册第 6 节。
3. **不报数字**：不要说"支持上千并发""日活多少"。可以说"七百多项自动化测试""六个服务""四个能力"——这些是可验证的。精确口径以 PPT 为准，口播用"七百多项"最稳。

## 四、可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| 为什么第三方只有 1 个模型？ | 发布门禁按 Schema 判断：`required` 含 `messages` 才发布。摘要/生图/视觉不是 Chat 协议 |
| 计费怎么保证不重复扣？ | 一次调用一条账单 + 幂等键（requestId），失败不扣费，预扣 + 结算两段式 |
| 密钥怎么存的？ | AES-256-GCM 加密，主密钥在环境变量里，接口只返回掩码 |
| 多租户怎么隔离？ | 三种身份：JWT（网页）、`sk_`（第三方）、内部令牌（服务间），不可互换 |
| 为什么用 Nacos？ | 服务注册发现 + 配置热更新；换掉它要改的是注册中心适配层，不是业务代码 |
