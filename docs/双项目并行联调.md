# AICapabilityHub Pro 与原项目并行运行

本页描述推荐资源隔离。原项目 D:\AICapabilityHub 保留，Pro 工作区为 D:\AICapabilityHubPro；两套项目不共用 MySQL 数据卷。

## 端口和资源

| 项目 | MySQL | Nacos HTTP/gRPC | Sentinel |
|---|---|---|---|
| 原项目/默认模式 | 3306 | 8848 / 9848 | 8858 |
| Pro 并行模式 | 3307 | 8849 / 9849 | 8859 |

Pro Compose project 为 aicapabilityhubpro，容器 aihub-pro-mysql/nacos/sentinel/nginx，MySQL 卷 aihub-pro-mysql-data。中间件并行端口绑定 127.0.0.1；Compose 覆盖文件替换端口列表，工具不改写已有 .env。

Gateway 8080、服务 8081/8082/8083/8090、Web 5173 仍可能与另一套应用冲突；中间件隔离不代表两套应用相同端口也能同时绑定。占用时先核实，不停止未知服务。

## 推荐启动与状态

```powershell
python scripts/start_pro_local.py middleware
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.pro-local.yml ps
```

各应用启动命令见[上手与联调](上手与联调.md)。内部目录交接前，AI 用 start_leader_dev.py ai-chat-service --catalog-mode market；其余 Pro 服务使用并行配置入口。start_dev.py 默认端口不可混用。

覆盖文件使用 !override，需支持该标记的 Docker Compose，开发基线要求 2.24.4 或更新。首次新卷按 deploy/mysql/init/ 建表和演示数据；已有卷不会因修改环境变量自动更换密码或执行增量结构迁移。

## 数据与验收

不挂原项目卷，不把原服务进程当作 Pro 就绪。数据库测试使用单独验收卷/实例，不能清开发库中的 qa 行。E2E 自建资源，结束后停止并保留；不使用 down -v 或清卷升级。
