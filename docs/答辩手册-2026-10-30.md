## 一、一句话讲清项目

> AICapabilityHub Pro 是一个「AI 能力超市 + 自动收银台」：把大模型能力包装成有参数、有单价、有账单的商品，开发者按次调用，平台负责鉴权、限流、计费、对账和调用追踪。

如果老师只给你 30 秒，就说这三句：

1. **卖什么**：平台上架了几个 AI 能力（多轮对话 5 积分/次、长文本摘要 3 积分/次）。
2. **怎么卖**：开发者选能力 → 平台按该能力的参数模板给出表单 → 提交后先查余额 → 调模型 → 扣积分 → 出一张可核对的"小票"。
3. **凭什么不是玩具**：价格和上下架状态每次都回源核对，参数前后端双重校验，一次调用的会话、账单、积分流水用同一个 `requestId` 串起来，模型挂了自动降级且不收费。

### 用生活场景打比方

| 平台里的东西 | 相当于 |
|---|---|
| 能力市场 | 餐厅菜单，只展示在售的菜 |
| 在线调试台 | 点单台：选菜、填口味（参数）、看价格 |
| 积分账户 | 饭卡，先充值后消费 |
| 调用记录 / 账单 | 小票和消费流水，能对得上账 |
| 运营后台 | 后厨管理：上新菜、下架、改价、看今天卖了多少 |
| 网关（Gateway） | 门口的保安 + 唯一的收银通道，没卡不让进，进门先验身份 |

## 二、系统长什么样

```
浏览器（React 工作台，端口 5173）
        │  只请求 /api/**
        ▼
Spring Cloud Gateway（8080）——验 JWT、清理伪造身份头、按路由限流、注入可信用户身份
        │
        ├── user-service      (8081, user_db)        账号、积分、API Key
        ├── capability-service (8082, capability_db) 分类、能力目录、Schema、价格、上下架
        ├── billing-service    (8083, billing_db)    账单、用量统计
        └── ai-chat-service    (8090, ai_chat_db)    会话、执行、调用模型
                 │
                 └── OpenAI 兼容模型接口（本地默认 DeepSeek）
```

三条硬规矩，答辩时可以主动讲，显得懂架构：

1. **浏览器不直连业务服务**，统一走 `/api/**`，由网关做身份与限流。
2. **四个服务四个库，不跨库查询**，服务之间只走 HTTP 契约。
3. **业务服务不相信浏览器传来的身份**，只认网关注入的 `X-User-Id`，伪造 `X-User-Role` 无效。

## 三、一次点击背后发生了什么（核心链路，务必背下来）

用户在调试台点"发送消息"，服务端按顺序做 8 件事：

| # | 动作 | 失败会怎样 |
|---|---|---|
| 1 | 网关校验 JWT，把可信身份写进请求头 | 401 / `code=1001`，前端跳登录 |
| 2 | 按 `capability_id` **实时**读取能力目录（不缓存） | 目录不可用 → `4002`，不会瞎猜价格 |
| 3 | 校验能力状态：必须 `online`，且执行器已实现 | 下架/未知能力 → `2002`、`2008` |
| 4 | 用该能力的 JSON Schema 复验参数 | 参数不符 → `2001`（前端也会先拦一次） |
| 5 | 调 user-service 预检余额 | 余额不足 → `3001`，不会先扣再报错 |
| 6 | 执行：聊天走多轮上下文，摘要走单次执行 | 模型超时/坏响应 → 降级话术 + `degraded=true` |
| 7 | 落库会话与消息，调 billing 记账并扣积分 | 失败回滚本地事务，按 `requestId` 对账 |
| 8 | 返回"小票"：实际费用、账单号、耗时、`requestId` | 前端展示回执，可到调用记录核对 |

**降级的含义**：模型不可用时不让用户白等，返回兜底话术，状态记 `degraded`，**实际扣费 0**，但调用记录仍然保留——所以"失败率/降级次数"在统计里看得见。这是很多课程项目没有的设计点。

**为什么价格每次都要重新查**：价格和上下架是运营随时会改的，缓存 5 分钟就可能出现"按旧价扣费"。宁可多一次内部调用，也不让账对不上。

## 五、怎么把它跑起来

### 5.1 前置条件

Docker Desktop（已启动）、Python 3.12+、Node 20+、JDK 21、Maven 3.9+。

### 5.2 启动顺序（六个终端，缺一不可）

```powershell
# 0) 中间件：MySQL 3307 / Nacos 8849 / Sentinel 8859
python scripts/start_pro_local.py middleware

# 1) 三个业务服务
python scripts/start_pro_local.py user-service
python scripts/start_pro_local.py capability-service
python scripts/start_pro_local.py billing-service

# 2) AI 执行服务（严格内部目录模式）
python scripts/start_leader_dev.py ai-chat-service --catalog-mode internal

# 3) 网关与前端
python scripts/start_pro_local.py gateway
python scripts/start_leader_dev.py web
```

启动完打开 <http://localhost:5173>。

### 5.3 演示账号

| 账号 | 密码 | 用途 |
|---|---|---|
| `demo` | `demo123456` | 主演示账号，100 积分 |
| `demopoor` | `demo123456` | 0 积分，演示"余额不足" |
| `demodisabled` | `demo123456` | 已禁用，演示"账号停用" |

> 管理员只能用离线命令创建，不能在页面上注册成管理员——这本身就是一个可以讲的权限设计点。

### 5.4 答辩前 5 分钟：把数据恢复干净

彩排会留下乱七八糟的调用记录和扣费，正式演示前执行：

```powershell
# 先看会删多少（只统计，不改数据）
python scripts/reset_demo_data.py

# 确认后执行：清空调用记录/会话/密钥/积分流水，demo 积分回到 100
python scripts/reset_demo_data.py --yes
```

脚本只动演示账号和三类流水，**不会重导 seed、不改能力目录和价格**。

### 5.5 模型两种模式

`services/ai-chat-service/.env` 里四个开关：

```ini
USE_MOCK=false                                   # true=本地模拟，false=真实供应商
MODEL_BASE_URL=https://api.deepseek.com/v1
MODEL_API_KEY=sk-xxxx                            # 只放本地，不进仓库
MODEL_NAME=deepseek-flash                        # 必须和供应商目录一致
```

- 网络不稳/断网时：把 `USE_MOCK=true` 改回来，重启 AI 服务，照样能完整演示（回执会标"本地模拟"，这是诚实的）。
- 真实模式下回执显示"模型执行"，能看到真实耗时和 token 数。

## 六、15 分钟答辩脚本

> 原则：**先给结论，再给证据；每讲一个功能，就在屏幕上做出一个结果。**
> 下面的时间是节奏参考，不是硬性规定。

### 0:00–1:30　开场（讲清楚"是什么、解决什么问题"）

话术：

> 我们做的是一个 AI 能力开放平台。现在很多团队要用大模型，但会遇到三个问题：能力散落在各个接口里、调用花了多少钱说不清、出了问题没法追。
> 我们的做法是把 AI 能力当成商品来管理：有目录、有参数、有单价、有账单、有追踪。用户按次付费，平台负责计量和对账。

同时打开工作台首页（有积分、调用趋势、最近调用）。

### 1:30–3:00　总览与架构（一页 PPT 或 README 架构图）

讲三句话：前端只走 `/api`；网关做身份和限流；四个服务四个库，不跨库。

### 3:00–6:00　主流程演示：一次真实调用

1. 进「能力市场」，指出两张卡片的**单价不同**（5 分 / 3 分），点「参数说明」展示 Schema。
2. 点「开始调试」，URL 带上 `capability_id`，表单是按该能力的参数模板生成的。
3. 输入一段中文问题，点发送。
4. 等 2–4 秒，指着回执念：**实际费用 5 积分、账单号、耗时、requestId**。
5. 右上角进「调用记录」，说明余额从 100 变 95，最新一条就是刚才那次，点击行能看完整 requestId。

要点台词：

> 这张回执不是前端算的，是服务端结算后返回的。价格来自能力目录，扣费走积分服务，账单落在计费服务，三者用同一个 requestId 对齐。

### 6:00–8:00　第二个能力：长文本摘要

切到「长文本摘要」（3 积分/次），粘贴一段材料，生成摘要。

台词：

> 同一个入口，不同能力有不同的输入 Schema 和不同的单价。摘要是一次性执行，不写会话；聊天是多轮，带上下文。执行器是白名单的，目录里如果出现平台没实现的编码，会被明确拒绝，不会变成任意接口代理。

### 8:00–10:00　运营后台（换管理员登录）

1. 用 `admin` 登录，进「运营后台」。
2. 展示能力列表：上架/草稿状态、单价、分类。
3. 「分类管理」展示分类维度。
4. 「平台用量」展示全站调用次数、消耗积分、调用用户数——和刚才 demo 的调用能对上。

台词：

> 普通用户进这个页面会被服务端拒绝，前端也会提示"无运营权限"。权限不是在页面上藏起来，是后端真的校验。

（可选，时间够再做）：新建一个草稿能力，填 Schema 和价格 → 保存 → 市场看不到（因为草稿）→ 上架 → 市场出现 → 再下架。

### 10:00–12:00　负例演示（最加分的一段）

按时间选 1–2 个即可：

- **余额不足**：用 `demopoor` 登录，点发送 → 提示积分不足，**不会调用模型**，也不产生账单。
- **参数非法**：把必填项留空 → 前端先拦；绕过前端直接打接口 → 服务端返回 `2001` 参数不符。
- **模型异常**：讲设计即可——模型超时/坏响应时返回兜底话术，`degraded=true`，**扣 0 积分**，但调用记录保留，所以能在统计里看到降级次数。
- **伪造身份**：说明业务服务只认网关注入的身份头，伪造 `X-User-Role: admin` 无效。

台词：

> 一个系统靠不靠谱，不看好路径，看坏路径。这些拒绝都发生在调模型之前，所以既不会白花钱，也不会把错误算到用户账上。

### 12:00 前可选加分项：外部客户端零改造接入

如果老师问"这东西别人怎么用"，直接打开 Cherry Studio 之类支持 OpenAI 协议的客户端：

| 配置 | 值 |
|---|---|
| Base URL | `http://localhost:8080/v1` |
| API Key | 平台「账号设置 → API Key」里创建的 Secret（`sk_...`） |
| 模型 | `deepseek-flash` |

发一条消息，回到平台「调用记录」，能看到这次调用和扣费——**外部程序用的也是同一套计量**。

台词：

> 很多平台做鉴权就只做鉴权。我们把 OpenAI 协议接进来之后，外部客户端每问一句，平台上就多一条可追溯的账单。这才是"能力开放"。

注意：Secret 只在创建时显示一次；演示前先建一把新的并保存好，别现场找。

### 12:00–14:00　工程与质量（讲"我们怎么保证它是对的"）

打开 GitHub 的 Actions 页面或本地报告，讲：

- 四个服务共 369 项数据库测试，零跳过零失败；网关 35 项。
- 真实服务 E2E：隔离 MySQL + 真实进程 + 真实浏览器，两种目录模式各 20+ 项。
- 浏览器验收覆盖桌面和 390px 手机，包含 Settings 与管理员 Console。

台词：

> 我们不是"点了一遍没报错"，而是每次改动都跑同一套可重复的验收，报告和截图都留档。

### 14:00–15:00　收尾

> 这个项目把"AI 能力"从一次函数调用，做成了可运营、可计量、可追责的商品。后面可以扩展的方向是：更多执行器（视觉、语音）、按 token 阶梯计价、真实支付接入。

## 七、老师最可能问的 12 个问题

**Q1：这和直接调 OpenAI/DeepSeek 接口有什么区别？**
直接调只有"请求-响应"。我们多了四层：统一身份与限流、能力目录与参数约束、按次计量与账单、跨服务的调用追踪。企业里真正难的是后四层。

**Q2：为什么不用一个单体服务，非要拆四个？**
按"人/钱/货/执行"拆，边界清晰，三个人可以并行开发且互不阻塞；每个服务独立库，避免跨库耦合。代价是分布式一致性，所以我们用 `requestId` 做对账而不是强一致。

**Q3：分布式事务怎么保证？**
不保证强一致，明确说出来更加分：本地会话事务与远端记账不是原子的。远端记账成功、本地提交失败时，按 `requestId` 对账，绝不盲目重试模型（因为会重复扣费）。

**Q4：怎么防止用户刷接口/超量调用？**
网关按路由做 Sentinel 限流（如 chat 20 QPS），超限返回 429 + `code=4001`；兑换接口单独限流。

**Q5：积分会不会扣错？**
余额有版本号做乐观锁；扣费在账单落库后按 `unit_price` 结算；降级执行费用为 0。页面上余额、流水、账单三处能互相核对。

**Q6：价格改了，正在进行的调用按哪个价？**
按本次调用读到的目录价，读到的价格同时写进账单的 `unit_price`，事后可追溯。

**Q7：能力下架了，用户还能调吗？**
不能。每次执行都回源校验 `status=online`，下架立即生效，不需要等缓存过期。

**Q8：参数校验为什么前后端都要做？**
前端为了体验（即时提示），后端为了安全（前端可绕过）。后端用能力自带的 JSON Schema 复验，Schema 由运营配置，不写死在代码里。

**Q9：模型挂了怎么办？**
降级：返回兜底话术，标记 `degraded`，不计费但保留记录，统计里能看到降级率。不会让用户看到 500。

**Q10：JWT 和 API Key 什么关系？**
JWT 是登录态（24 小时）；API Key 是给程序调用用的长期凭证，创建时只显示一次 Secret，之后只存掩码；用 Access Key + Secret 兑换一个短 TTL 的 JWT 再调接口。

**Q11：为什么管理员不能在页面注册？**
提权面越小越好。管理员只能由负责人在服务器上用离线命令创建，且已有账号拒绝覆盖。

**Q12：这个项目你个人做了什么？**
按实际分工答，讲清楚"我负责的那块的难点 + 我怎么验证的"。例如组长：网关身份治理 + 执行链闭环 + 集成验收。

## 八、现场风险预案

| 风险 | 表现 | 处理 |
|---|---|---|
| 断网 / 供应商限流 | 回复变成"模型服务暂时不可用" | 切 `USE_MOCK=true` 重启 AI 服务，说"这是本地模拟模式，链路和计费逻辑完全一致" |
| 模型很慢 | 转圈超过 10 秒 | 提前把 `MODEL_TIMEOUT` 讲清楚；或改用短问题，别现场贴长文 |
| 端口被占 | 启动报 "Port xxx is occupied" | 先关掉上次没退干净的服务；不要盲目 kill 未知进程 |
| 数据太乱 | 余额只剩几十、记录一堆 | 提前跑 `python scripts/reset_demo_data.py --yes` |
| 忘记管理员密码 | 进不去运营后台 | 用 `admin / Admin@2026`；不行就用离线命令重建一个 |
| 浏览器缩放异常 | 布局挤在一起 | 保持 100% 缩放，窗口 ≥1440×900 |

| 运营：平台用量 | `GET /api/billing/statistics` |

统一响应：`{"code":0,"message":"success","data":{...},"requestId":"..."}`。
常见错误码：`1001` 未认证、`1005` 用户不存在或禁用、`2001` 参数不符 Schema、`2002` 能力不存在或下线、`2008` 无可用执行器、`3001` 积分不足、`4001` 限流、`4002` 下游不可用、`5001/5002` 模型超时/坏响应。
